## 十、阶段 G：正式学习最小指针与数组关系（60-75 分钟）

教材定位：第10章“管理内存与低级数据结构”，10.1“指针与数组”，印刷页 175-182，PDF 约 193-200。重点阅读 10.1.1“指针”、10.1.3“数组”、10.1.4“指针算术”和 10.1.5“索引”；10.1.2“指向函数的指针”本次只略读，不要求掌握。

创建 `day4/pointer_basics.cpp`，依次验证：

```cpp
float value = 1.0f;
float* pointer = &value;
```

需要解释：

- `float*` 是指向 `float` 的指针类型。
- 指针变量保存地址，而不是直接保存那个浮点值。
- `&value` 取得 `value` 的地址。
- `*pointer` 解引用并访问地址中的值。
- 修改 `*pointer` 为什么会改变 `value`。

然后增加固定数组：

```cpp
float values[3] = {1.0f, 2.0f, 3.0f};
```

观察并解释：

- 数组元素在逻辑上按顺序排列。
- `values` 在许多表达式中可以转换成指向首元素的指针。
- `values[i]` 与通过指针访问第 `i` 个元素的关系。
- `pointer + 1` 移动到下一个同类型元素，不是简单增加一个字节。
- 指针不能因为“可以移动”就访问数组边界之外。

暂时不学习多级指针、函数指针、智能指针和复杂指针声明。

教材联系：3.2.1 的 `vector` 与第10章 10.1 的指针和数组。`data()` 可作为从标准容器过渡到低级指针接口的补充知识。

在 `pointer_basics.cpp` 中增加：

```cpp

```

- `values` 是管理对象，`values.data()` 得到指向元素存储区域的指针。
- `data[0]` 与 `values[0]` 访问同一个元素。
- 空向量的 `data()` 结果不能被解引用。
- 当 `vector` 扩容或被重新分配后，之前保存的元素指针可能失效；本次只建立意识，不深入内部实现。

教材定位：5.2“迭代器”、5.2.1“迭代器的类型”、5.2.2“迭代器的操作”、5.3“用迭代器代替索引”，印刷页 80-84，PDF 约 98-102。

只完成最小比较：

```text
索引遍历       -> values[i]
范围 for       -> for (float value : values)
迭代器遍历     -> begin() 到 end()
```

理解：

- `begin()` 指向第一个元素位置。
- `end()` 表示尾后位置，不是最后一个元素。
- 迭代器与指针有相似操作，但不能简单断言所有迭代器都是裸指针。
- CPU Vector Add 仍优先保留索引版本，因为它与 CUDA 的线程索引映射最直观。

## 十四、阶段 K：更完整的 CUDA Vector Add 预览（30-45 分钟）

本阶段没有对应的《Accelerated C++》教材页码，只做 C++ 知识到 CUDA 的映射。

按顺序认识一次 CUDA 程序的生命周期：

```text
CPU 准备输入数据
-> GPU 侧申请空间
-> 输入数据从 CPU 复制到 GPU
-> 启动 Vector Add Kernel
-> 等待并检查错误
-> 输出数据从 GPU 复制回 CPU
-> 对照 CPU 结果验证
-> 释放 GPU 资源
```

认识但暂不要求独立写出：

```cpp
int i = blockIdx.x * blockDim.x + threadIdx.x;

if (i < N)
{
    output[i] = a[i] + b[i];
}
```

额外理解：

- `threadIdx.x`：线程在线程块内的编号。
- `blockIdx.x`：线程块编号。
- `blockDim.x`：每个线程块的线程数量。
- 总线程数通常向上取整，因此必须检查 `i < N`。
- Kernel 的数学规则与 CPU Vector Add 相同，变化的是任务分配方式。

若 CPU Vector Add、指针或边界仍解释不清，只阅读流程，不复制完整 CUDA 程序。
